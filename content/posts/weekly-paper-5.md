# Q1. 20층 시그모이드 — 입력층 가중치가 안 변한다

> 20층 신경망에 시그모이드를 썼어요. 출력층 근처는 잘 학습되는데 입력층 근처 가중치는 몇 에포크가 지나도 그대로예요. 원인은? 어떻게 확인하고 해결할 건가요?

## 한 줄 답

**기울기 소실.** 층별 gradient를 찍어 확인 → 시그모이드를 ReLU + He 초기화로 교체 → 다시 찍어 검증.

## 질문의도

| 보는 것 | 내용 |
|---|---|
| 추론 | 깊다 + 시그모이드 + 앞쪽만 안 배운다 → 원인을 떠올리는가 |
| 확인 | 짐작에서 멈추지 않고 숫자로 확인하는가 |
| 검증 | 고친 뒤 다시 확인하는가 |

## 답변

### 1. 의심 — 기울기 소실

- gradient는 출력층 → 입력층으로 한 층씩 전달되고, 각 층은 그만큼 가중치를 움직인다
- 안 움직인다 = **gradient가 거의 0으로 도착**했다
- 시그모이드는 gradient를 넘길 때 **최대 1/4로 줄인다** → 20층이면 1/4을 20번 곱해 사실상 0

![gradient가 출력층에서 입력층으로 갈수록 1/4씩 줄어 사라지는 모습](/images/weekly-paper-5/q1-vanishing.svg)

### 2. 확인 — 층별 gradient 크기 출력

```python
loss.backward()
for name, p in model.named_parameters():
    print(name, p.grad.norm().item())
```

- 입력 쪽으로 갈수록 작아지면 **기울기 소실 확정**

### 3. 해결 — 시그모이드 → ReLU + He 초기화

![시그모이드는 최대 1/4로 줄이고, ReLU는 그대로 넘긴다](/images/weekly-paper-5/q1-sigmoid-vs-relu.svg)

| 방법                  | 왜                                                                   |
| ------------------- | ------------------------------------------------------------------- |
| **ReLU**            | 양수에서 gradient를 **그대로(×1)** 넘김 → 앞쪽까지 살아서 감                          |
| **He 초기화**          | ReLU는 음수를 0으로 버려 값이 절반씩 줄어듦 → **처음 가중치를 조금 크게** 잡아 보완               |
| Batch Normalization | 각 층 입력을 평균 0·분산 1로 다시 맞춤 → 기울기가 0인 구간으로 빠지는 걸 막음 (부족할 때 추가)         |
| Residual Connection | 층 출력에 입력을 그대로 더함(`f(x) + x`) → gradient가 곱셈 없이 앞쪽까지 통과 (더 깊어질 때 추가) |

**바꾸면 잃는 것** — 시그모이드는 결과가 0~1이라 확률로 읽기 좋아서 썼다.

| 잃는 것 | 대처 |
|---|---|
| 결과가 0~1이 아님 | 중간 층만 ReLU, **마지막 층은 시그모이드·소프트맥스 유지** |
| 음수가 0 → 죽은 뉴런은 못 살아남 | Leaky ReLU 같은 변형 |
| 값 상한 없음 → 학습률 크면 튐 | He 초기화 + 학습률 재조정 |

### 4. 재검증

- 같은 코드로 gradient를 다시 출력 → 앞쪽 층이 살아났는지 확인

# Q2. 100만 개 데이터 — GPU에 한 번에 못 올린다

> 100만 개를 GPU에 한 번에 못 올려요. 배치 크기를 어떻게 정할 건가요? 아주 작게 / 아주 크게 잡으면 각각 어떤 문제가 있나요?

## 한 줄 답

**나눠서 올린다(미니배치).** 32부터 2배씩 키워보며 메모리·속도·validation 성능으로 정한다. 들어가는 최대 크기 ≠ 최선.


## 답변

### 1. 전제 — 나눠서 올린다

- 64개씩 묶어 GPU에 하나씩 보낸다 = **배치**
- 배치마다 예측 → loss → 고치기 한 번

![100만 개를 64개씩 잘라 GPU로 하나씩 보낸다](/images/weekly-paper-5/q2-minibatch.svg)

### 2. 정하는 법

1. **32 또는 64**로 시작 — 대부분 GPU에 들어가고, GPU가 놀지 않고, 학습이 흔들리지 않는 무난한 출발점
2. **2배씩** 키운다 (128 → 256 → 512)
3. 메모리 에러 → **바로 전 크기가 상한**
4. 상한 안에서 **속도 + validation 성능**으로 선택

![32/64 시작 → 2배씩 → 메모리 상한 → 그 안에서 선택](/images/weekly-paper-5/q2-batch-size.svg)

### 3. 너무 작으면 vs 너무 크면

| | 너무 작음 (10개) | 너무 큼 (10만 개) |
|---|---|---|
| gradient | 흔들림 | 안정적 |
| 1 epoch 고치는 횟수 | 10만 번 | 10번뿐 |
| GPU | 놀아서 느림 | 메모리 부족 |
| 새 데이터 성능 | 약간의 흔들림이 도움 | 나빠질 수 있음 |

### 4. 원하는 크기가 안 들어가면

- **gradient accumulation** — 작은 배치 여러 개의 gradient를 모아 한 번에 고침
- 메모리는 작게, 효과는 큰 배치처럼
