## Q1. Loss가 줄다가 커지더니 NaN이 됐습니다. 무엇을 확인할 건가요?

> `model.fit()`으로 학습을 돌렸는데, loss 값이 처음엔 잘 줄어들다가 어느 순간부터 점점 커지더니 결국 NaN이 되어버렸어요. 어떤 원인들을 의심해볼 건가요? 각 원인을 어떻게 확인할 건가요?

저는 먼저 "loss가 갑자기 NaN이 된 게 아니라, 점점 커지다가 NaN이 됐다"는 패턴에 주목하겠습니다.

### Epoch와 batch — 어느 단위로 볼 것인가

전체 데이터를 한 번 학습하는 것을 epoch, 데이터를 작은 묶음으로 나눠 한 번 학습하는 단위를 batch라고 합니다.

| | 뜻 | 학습 한 번에 찍히는 로그 |
|---|---|---|
| **epoch** | 전체 데이터를 한 바퀴 | 몇 줄 |
| **batch** | 작은 묶음 하나 | 수십~수백 줄 |

Epoch 결과만 보면 중간 과정을 놓칠 수 있기 때문에 batch별 loss를 확인해서 언제부터 문제가 시작됐는지 보겠습니다.

![Epoch 단위 로그와 batch 단위 로그의 차이. epoch 단위로는 loss가 nan이라는 한 줄만 남아 언제부터 망가졌는지 알 수 없지만, batch 단위로는 loss가 여러 배씩 커지는 계단이 그대로 보인다](/images/weekly-paper-2/q1-epoch-vs-batch.svg)

```python
log = tf.keras.callbacks.LambdaCallback(
    on_batch_end=lambda batch, logs: print(batch, logs['loss'])
)
model.fit(X, y, callbacks=[log])
```

### Loss가 망가지는 모양으로 원인을 좁힌다

Batch별로 찍어보면 크게 두 가지 모양이 나옵니다.

![원인별 loss 곡선 모양 세 가지. 발산형은 계단처럼 몇 배씩 커지고, 즉사형은 정상이다가 한 번에 NaN이 되고, 지뢰형은 평온하다가 특정 batch에서 한 번에 폭발한다](/images/weekly-paper-2/q1-fingerprints.svg)

| 모양 | 의심할 원인 | 확인 방법 |
|---|---|---|
| **여러 batch에 걸쳐 loss·gradient가 계속 커짐** | 학습률이 너무 큼<br>입력 데이터의 스케일 차이가 큼 | 학습률을 낮춰 다시 학습<br>`np.abs(X).max(0)`으로 열별 크기 비교 후 표준화 |
| **특정 batch에서 갑자기 NaN** | 그 batch에 NaN·inf·이상치가 있음<br>직접 만든 loss 함수의 계산 문제 | `np.isnan(X).sum()`, `np.percentile(y,[99,100])`<br>0으로 나누기·`log(0)`이 생기는지 확인 |

여러 batch에 걸쳐 loss와 gradient가 계속 커진다면 학습률이 너무 크거나 입력 데이터의 스케일 차이가 커서 학습이 발산하는 것을 의심하고, 학습률을 낮추거나 데이터를 표준화해서 다시 학습해보겠습니다.

학습률은 산을 내려갈 때의 보폭에 해당합니다. 보폭이 너무 크면 골짜기를 건너뛰어 반대편 더 가파른 곳에 착지하고, 그래서 다음 걸음은 더 크게 튑니다. 이것이 발산의 구조입니다.

![학습률과 보폭. 적당한 보폭은 골짜기 바닥으로 수렴하지만, 너무 큰 보폭은 골짜기를 건너뛰어 반대편 더 높은 곳에 착지하고, 그러면 기울기가 더 커져서 다음 걸음은 더 멀리 튄다](/images/weekly-paper-2/q1-lr-overshoot.svg)

입력 스케일이 문제가 되는 이유도 같습니다. 어떤 열의 값이 1000배 크면 그 방향의 gradient도 1000배가 되므로, 학습률을 건드리지 않아도 걸음이 1000배가 되기 때문입니다.

반대로 특정 batch에서 갑자기 NaN이 된다면 그 batch에 NaN, inf, 이상치가 있는지 확인하겠습니다. 또한 직접 만든 loss 함수가 있다면 0으로 나누기, log(0) 같은 계산이 발생하는지도 확인하겠습니다.

즉, 원인을 무작정 하나씩 확인하기보다 loss가 망가지는 모양을 먼저 보고 원인의 범위를 좁히겠습니다.

## Q2. 만족도 1~5점을 회귀와 분류 중 무엇으로 예측할 건가요?

> 고객 만족도 설문 결과(1점~5점)를 예측하는 모델을 만들어야 해요. 이 문제는 회귀로 풀 수도 있고, 5개 범주에 대한 분류로 풀 수도 있어요. 어떤 방식을 선택할 건가요? 각 방식의 장단점을 들어 설명해 주세요.

저는 먼저 "예측 결과를 어디에 사용할 것인가?"를 확인하겠습니다.

### 회귀와 분류

만족도의 점수 차이까지 중요하다면 회귀가 적합합니다. 실제가 5점일 때 4점을 예측한 것보다 1점을 예측한 것을 더 큰 오류로 보기 때문입니다. 다만 3.7점처럼 실제 설문에는 없는 값이 나올 수 있고, 1→2와 4→5의 차이가 동일하다고 가정한다는 한계가 있습니다.

반대로 분류는 정확히 1~5점 중 하나를 예측하고 각 점수일 확률도 얻을 수 있습니다. 하지만 일반적인 분류는 1 < 2 < 3 < 4 < 5라는 순서를 제대로 활용하지 못합니다.

| | 회귀 | 분류 |
|---|---|---|
| **1~5점을 보는 관점** | 간격이 일정한 숫자 | 서로 무관한 5개의 이름표 |
| **장점** | 5→4보다 5→1을 더 큰 오류로 취급 | 설문에 있는 값만 예측<br>각 점수일 확률을 얻을 수 있음 |
| **한계** | 3.7점처럼 없는 값이 나옴<br>1→2와 4→5의 차이를 같다고 가정 | 1 < 2 < 3 < 4 < 5라는 순서를 활용하지 못함 |

### 순서형(Ordinal) 모델

그래서 저는 실제 프로젝트라면 순서형(Ordinal) 모델도 함께 비교하겠습니다. 순서형 모델은 1~5점을 서로 완전히 다른 종류로 보지도 않고, 간격이 똑같은 숫자로 보지도 않습니다. "순서는 있지만 점수 사이의 간격은 꼭 같지는 않은 등급"으로 보는 방식입니다.

![세 가지 관점의 비교. 회귀는 순서와 등간격을 모두 가정하고 분류는 둘 다 없다고 가정하지만, 순서형은 순서는 있고 간격은 일정하지 않은 것으로 본다](/images/weekly-paper-2/q2-ordinal-nature.svg)

예를 들어 모델이 "1점보다 높은가? → 2점보다 높은가? → 3점보다 높은가? → 4점보다 높은가?"를 차례로 판단하도록 만들 수 있습니다.

![순서형 모델의 구조. 5개 중 하나를 고르는 대신 1점 초과인가, 2점 초과인가, 3점 초과인가, 4점 초과인가를 각각 예측한 뒤 누적확률의 차이로 각 점수의 확률을 구한다](/images/weekly-paper-2/q2-ordinal-method.svg)

만족도처럼 순서는 확실하지만 점수 사이의 심리적 간격은 정확히 알 수 없는 데이터에 잘 맞습니다.

### 평가 지표

평가할 때도 단순 정확도만 보지 않겠습니다. 5→4와 5→1을 똑같은 오답으로 보는 것은 적절하지 않기 때문입니다.

![분류와 회귀의 오답 벌점 차이. 실제 5점을 4점이라 예측하나 1점이라 예측하나 분류는 같은 벌점을 주지만 회귀는 거리에 비례해 벌점을 준다](/images/weekly-paper-2/q2-penalty.svg)

그래서 평균적으로 몇 점 차이로 틀렸는지를 보는 MAE나, 멀리 틀릴수록 더 큰 벌점을 주는 QWK도 함께 확인하겠습니다.

| 지표 | 무엇을 보나 | 5점을 1점이라 틀렸을 때 |
|---|---|---|
| **정확도** | 맞았나 틀렸나만 | 5점을 4점이라 틀린 것과 동일 |
| **MAE** | 평균 몇 점 차이로 틀렸나 | 4배 더 큰 오류 |
| **QWK** | 멀리 틀릴수록 더 큰 벌점 | 16배 더 큰 벌점 |

```python
from sklearn.metrics import mean_absolute_error, cohen_kappa_score

mean_absolute_error(y_true, y_pred)
cohen_kappa_score(y_true, y_pred, weights='quadratic')   # QWK
```
