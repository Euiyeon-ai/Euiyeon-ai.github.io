# Q1. 진열대 CCTV — "무엇이 있나"를 넘어 "몇 개, 어디에"까지

> 매장 CCTV 영상에서 '진열대에 상품이 몇 개, 어디에 놓여 있는지'까지 파악해야 해요. 이미지 분류 모델을 그대로 사용하면 어떤 한계가 있을까요? 객체 인식은 이 문제를 어떻게 다르게 접근하나요?

## 한 줄 답

**이미지 분류는 사진 한 장에 답을 하나만 낸다.** 그래서 "음료 진열대"라고는 말해도 **콜라가 몇 개인지, 어느 칸에 있는지는 출력 자체에 없다.** 객체 인식은 **상품마다 박스 · 종류 · 점수**를 따로 낸다. **박스 수가 곧 개수, 박스 좌표가 곧 위치**다.

## 답변

![이미지 분류와 객체 인식의 출력 비교](/images/weekly-paper-9/wp9-q1-cls-vs-det.svg)

### 1. 문제 — 분류 모델은 질문의 절반에 답할 수 없다

매장이 알고 싶은 것은 세 가지다.

| 질문 | 이미지 분류 | 필요한 것 |
|---|:-:|---|
| 무엇이 있나? | △ 사진 전체에 대해 하나 | 상품 **하나하나**의 종류 |
| **몇 개**인가? | ✗ | 상품마다 따로 찾아 세기 |
| **어디에** 있나? | ✗ | 상품마다 좌표 |

분류 모델의 출력은 `[음료 진열대 0.97, 과자 진열대 0.02, …]` 같은 **확률 묶음 하나**다. 콜라가 3개든 30개든, 왼쪽에 있든 오른쪽에 있든 **같은 답**이 나온다.

### 2. 원인 — 분류는 "사진 1장 → 라벨 1개"로 설계되어 있다

**① 출력 구조에 개수 · 위치가 들어갈 자리가 없다**

CNN이 사진 전체를 훑은 뒤 마지막에 **평균을 내서(Global Average Pooling)** 클래스 점수 하나로 줄인다. 이 과정에서 "어디에 무엇이 있었는지"가 합쳐져 사라진다.

**② 학습 데이터에도 위치 정보가 없다**

분류 데이터의 정답은 "이 사진 = 음료 진열대" 한 줄이다. 모델은 **위치를 배울 기회 자체가 없다.**

**③ CCTV 속 상품은 작다**

매장 전체를 찍는 CCTV에서 상품 하나는 수십 픽셀이다. 224×224로 줄이면 **몇 픽셀**만 남는다. 사진 전체의 특징(조명 · 선반 색)에 묻혀 개별 상품이 거의 보이지 않는다.

> **분류 모델로 억지로 풀 수는 없나?**
>
> | 우회 방법 | 어떻게 | 한계 |
> |---|---|---|
> | **칸으로 잘라 각각 분류** | 진열대를 격자로 잘라 칸마다 "콜라 / 빈 칸" 분류 | 상품이 칸 경계에 걸리면 **두 번 세거나 놓친다** · 카메라 각도가 바뀌면 칸을 다시 정해야 한다 |
> | **개수를 숫자로 바로 예측** | 출력을 "콜라 개수" 같은 숫자로 학습 | **어디에** 있는지는 여전히 모른다 · 상품 종류가 늘면 출력도 늘어난다 |
> | **여러 라벨 분류 (multi-label)** | "콜라 있음 · 사이다 있음"을 동시에 | **있다 / 없다**까지만 안다 |
>
> 셋 다 "개수와 위치를 물체 단위로" 내지 못한다. 이 문제를 처음부터 풀도록 만든 것이 객체 인식이다.

### 3. 해결책 — 객체 인식은 "물체마다" 답한다

| | 이미지 분류 | 객체 인식 (Object Detection) |
|---|---|---|
| 질문 | 이 사진은 **무엇**인가? | **무엇이 어디에** 있는가? |
| 출력 | 라벨 **1개** | 물체마다 **(박스 4개 숫자 + 종류 + 점수)**, 개수는 사진마다 다름 |
| 정답 데이터 | 사진마다 라벨 한 줄 | 물체마다 **박스 좌표 + 종류** (XML · JSON) |
| 손실(loss) | 분류 오차 1개 | **위치 오차 + 분류 오차** |
| 평가 | Accuracy · F1 | **IoU · mAP** |

#### ① 어떻게 "물체마다" 찾을까 — 후보 박스를 깔고 고른다

SSD 같은 모델은 사진 위에 **크기 · 모양이 다른 후보 박스를 촘촘히 깔아 둔다.** (SSD300은 **8,732개**)
후보 박스마다 두 가지를 동시에 예측한다.

1. **무엇인가?** → 배경 / 콜라 / 사이다 / 생수 점수
2. **어디로 옮길까?** → 진짜 상품에 딱 맞도록 박스를 얼마나 움직이고 늘릴지

같은 상품 주위에 비슷한 박스가 여러 개 남으면 **NMS**가 점수 1등만 남기고 나머지를 지운다. 남은 박스 하나 = 상품 하나.

![CCTV 프레임에서 상품 개수와 위치를 얻는 과정](/images/weekly-paper-9/wp9-q1-pipeline.svg)

#### ② 개수와 위치는 박스에서 바로 나온다

```python
from collections import Counter

pred = model([frame])[0]          # {"boxes": (N, 4), "labels": (N,), "scores": (N,)}
keep = pred["scores"] >= 0.5      # 확신 있는 박스만
boxes, labels = pred["boxes"][keep], pred["labels"][keep]

counts = Counter(classes[l] for l in labels.tolist())   # 개수 : 종류별 박스 수
# {'콜라': 3, '사이다': 1, '생수': 5}

cx = (boxes[:, 0] + boxes[:, 2]) / 2                    # 위치 : 박스 중심
cy = (boxes[:, 1] + boxes[:, 3]) / 2
shelf = torch.bucketize(cy, shelf_lines)               # 중심의 높이로 몇 번째 단인지
```

**빈 칸**은 모델이 직접 찾지 않아도 된다. 같은 단에서 **박스 사이 간격이 상품 하나보다 넓으면** 그곳이 빈 자리다.

#### ③ 진열대라서 더 신경 쓸 것

| 상황 | 문제 | 대응 |
|---|---|---|
| **상품이 빽빽하게 붙어 있다** | NMS가 겹친 **진짜 옆 상품**까지 지울 수 있다 | NMS 기준(IoU)을 조정하고, 빽빽한 장면용 데이터로 학습 (예: 진열대 전용 데이터셋 SKU-110K는 사진 한 장에 상품이 평균 100개 이상) |
| **상품이 작다** | 줄인 입력에서 몇 픽셀만 남음 | 입력 해상도를 키우거나, 진열대 부분만 잘라 넣기 · 여러 크기 특징맵을 쓰는 모델(SSD · FPN) |
| **종류가 수천 개** | 클래스가 너무 많아 탐지 모델 하나로는 어렵다 | **2단계** : ① "상품"이라는 한 종류로 위치만 찾고 → ② 잘라 낸 상품을 분류 모델로 종류 판별 |
| **CCTV 각도 · 가림 · 조명** | 손님 · 카트가 상품을 가림, 시간대별 조명 | 여러 프레임을 모아 판단 · 밝기 증강 · 카메라 위치 고정 |

> **박스로 부족하면? — 세그멘테이션**
>
> 박스는 직사각형이라 기울어진 상품이나 **빈 공간의 정확한 넓이**를 재기엔 거칠다. 픽셀 단위로 상품 영역을 나누는 **인스턴스 세그멘테이션**(Mask R-CNN 등)을 쓰면 더 정밀하다. 대신 정답을 만드는 비용이 훨씬 크다.

> **평가는 왜 정확도가 아니라 mAP인가?**
>
> 탐지에는 "맞았다"의 기준이 두 개다. **종류가 맞고**, **박스가 충분히 겹쳐야(IoU ≥ 0.5 등)** 한다. 여기에 **놓친 상품(FN)** 과 **없는데 그린 박스(FP)** 를 모두 반영해야 하므로 Precision · Recall을 합친 **mAP**로 잰다.
> 재고 관리가 목적이면 **개수 오차**(실제 개수와 센 개수의 차이)도 함께 본다.

### 4. 변화 — "진열대 사진"이 "재고 데이터"가 된다

| | 분류 모델 | 객체 인식 |
|---|---|---|
| 결과 | "음료 진열대" | **콜라 3 · 사이다 1 · 생수 5, 각 위치, 빈 칸 3** |
| 할 수 있는 일 | 사진이 어떤 진열대인지 구분 | **품절 칸 알림 · 시간대별 재고 변화 · 진열 위치 점검** |

사람이 매장을 돌며 세던 일을 CCTV가 몇 초마다 대신할 수 있다.

| | |
|---|---|
| **문제** | CCTV로 진열대 상품의 **개수와 위치**까지 알아야 한다 |
| **원인** | 이미지 분류는 **사진 1장 → 라벨 1개**. 출력과 학습 데이터 모두에 개수 · 위치가 없고, 작은 상품은 묻힌다 |
| **해결책** | **객체 인식** : 후보 박스마다 "무엇 · 어디"를 예측 → NMS로 정리 → 박스를 세고(개수) 좌표로 칸을 나눈다(위치) |
| **변화** | 진열대 사진이 **재고 수량 · 품절 위치 데이터**가 된다 |

**분류는 "무엇"까지, 객체 인식은 "무엇이 몇 개, 어디에"까지 답한다.**
