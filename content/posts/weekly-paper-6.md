# Q. 완전연결층만으로 만든 이미지 분류기 — 파라미터 폭발 + 위치에 취약

> 이미지 분류 모델을 완전연결층(Fully Connected Layer)만으로 만들었더니 파라미터 수가 수백만 개를 넘고, 사진 속 물체 위치가 조금만 바뀌어도 예측이 크게 달라져요. 왜 이런 문제가 생기고, CNN은 이 문제를 어떻게 해결하나요?



## 답변

### 1. FC는 사진을 어떻게 보나 — 픽셀 하나 = 입력 하나

사진을 FC에 넣으려면 먼저 **일렬로 편다(flatten)**. 100×100 흑백 사진이면 픽셀 10,000개가 입력 10,000개가 된다. 이 입력 하나하나가 다음 층의 뉴런 **전부**와 선으로 이어진다.

![완전연결은 모든 픽셀이 모든 뉴런과 이어지고, 합성곱은 3×3 창 안의 픽셀만 출력 하나로 이어진다](/images/weekly-paper-6/q1-fc-vs-cnn-connect.svg)

선 하나마다 가중치 하나. 그래서 첫 층 파라미터는 **픽셀 수 × 뉴런 수**.

| 입력 사진                | 뉴런 수 | 첫 층 파라미터 |
| -------------------- | ---- | -------- |
| 100×100 흑백 (10,000)  | 256  | 약 256만   |
| 224×224 컬러 (150,528) | 256  | 약 3,850만 |
|                      |      |          |

사진이 커지면 그대로 따라 커진다. 이게 문제 ①.

### 2. 왜 위치에 약한가 — 같은 뿌리

FC는 **"1번 칸에 무엇이 있었나"**를 1번 칸 전용 가중치로 외운다. 학습 사진에서 고양이가 늘 왼쪽에 있었으면, 왼쪽 픽셀에 붙은 가중치만 고양이를 배우고 오른쪽 픽셀에 붙은 가중치는 배운 적이 없다.

새 사진에서 고양이가 오른쪽으로 가면, 고양이 픽셀을 처리하는 건 **배운 적 없는 가중치**다. 사람 눈엔 같은 고양이인데 모델엔 처음 보는 입력이다.

![학습 때 왼쪽 픽셀 가중치만 배운 FC는 오른쪽으로 옮겨간 고양이를 못 알아보지만, CNN은 같은 필터가 어디서든 같은 특징을 찾는다](/images/weekly-paper-6/q1-shift.svg)

문제 ①과 ②는 별개가 아니다. **"위치마다 따로 가중치를 둔다"**는 설계 하나에서 둘 다 나온다. 위치마다 따로 두니까 많고, 위치마다 따로 두니까 옮기면 못 알아본다.

### 3. CNN은 어떻게 푸나 — 돋보기 하나를 돌려쓴다

CNN은 사진 전체를 한 번에 잇지 않는다. **3×3 같은 작은 창(필터, kernel)** 하나를 들고 사진 위를 한 칸씩 옮겨 다니며 "이 자리에 내가 찾는 모양이 있나"를 계산한다. 그 결과를 모은 게 **특징 맵(feature map)**.

핵심 장치 세 가지:

| 장치 | 무엇 | 푸는 문제 |
|---|---|---|
| **지역 연결** (local connectivity) | 출력 한 칸은 근처 3×3 픽셀만 본다 | ① 선 수가 9개로 줄어듦 |
| **가중치 공유** (weight sharing) | 같은 필터 9개 값을 사진 어디서나 재사용 | ① 사진 크기와 무관하게 파라미터 고정<br>② 물체가 옮겨가면 특징 맵의 반응도 같이 옮겨갈 뿐, 같은 필터가 잡아냄 (**이동 등변성**) |
| **풀링** (pooling) | 2×2 창에서 최대값만 남겨 크기를 절반으로 | ② 한두 칸 움직인 건 같은 창 안 → 결과 동일 (**이동 불변성**에 가까워짐) |

파라미터로 보면:

![로그 축 막대: FC 첫 층은 256만~3,850만, Conv 3×3 필터 32개는 320으로 사진 크기와 무관](/images/weekly-paper-6/q1-param-count.svg)

3×3 필터 하나 = 가중치 9개 + 편향 1개 = 10개. 필터 32개면 **320개**. 100×100이든 224×224든 그대로 320개다. FC 256만과 비교하면 약 8,000배 차이.

풀링이 위치 변화를 흡수하는 모습:

![4×4 특징 맵에서 반응이 한 칸 옆으로 옮겨가도 2×2 최대 풀링 결과는 같다](/images/weekly-paper-6/q1-pooling.svg)

### 4. 코드로 확인

```python
import torch.nn as nn

fc   = nn.Linear(100 * 100, 256)        # 100×100 흑백 → 뉴런 256
conv = nn.Conv2d(1, 32, kernel_size=3)  # 채널 1 → 필터 32개, 3×3

count = lambda m: sum(p.numel() for p in m.parameters())
print(count(fc))    # 2560256
print(count(conv))  # 320
```

### 5. 두 문제 → 두 해법, 한 장 정리

| | 완전연결(FC) | 합성곱(CNN) |
|---|---|---|
| 보는 범위 | 모든 픽셀을 한꺼번에 | 작은 창(3×3)씩 |
| 가중치 | 픽셀 위치마다 따로 | 필터 하나를 어디서나 재사용 |
| 파라미터 | 픽셀 수 × 뉴런 수 → 수백만 | 필터 크기 × 필터 수 → 수백 |
| 물체가 이동하면 | 배운 적 없는 가중치가 처리 → 흔들림 | 같은 필터가 잡음 → 특징 맵만 이동 |
| 외우는 것 | "어느 칸에 있었나" | "어떤 모양인가" |

- **① 파라미터가 너무 많다** → 지역 연결 + 가중치 공유
- **② 조금 움직였더니 못 알아본다** → 가중치 공유(위치 이동하면 특징맵도 이동) + 풀링(작은 위치변화에 대한 불변성)

### 6. CNN도 만능은 아니다

| 한계              | 왜                                                                                                           | 대처                                                                                                              |
| --------------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 회전·크기 변화        | 필터는 "옮기기"만 공유하지 "돌리기·키우기돌리기·키우"는 공유 안 함                                                                     | 데이터 증강(augmentation)으로 돌리고 키운 사진을 같이 학습                                                                         |
| 마지막 분류층은 여전히 FC | 특징 맵을 펴서 클래스 점수로 바꿔야 함                                                                                      | 합성곱·풀링을 여러 번 거쳐 **작아진 뒤** 붙이므로 파라미터 부담이 훨씬 덜함. Global Average Pooling으로 더 줄이기도 함                                |
| 큰 위치 변화         | 합성곱은 물체가 이동하면 **특징도 같이 이동할 뿐**, 위치 차이를 없애주지는 않음(등변성 ≠ 불변성). 풀링도 같은 창 안의 작은 이동만 흡수하고, 다른 창으로 넘어가면 결과 위치가 달라짐 | 깊은 층의 넓은 수용 영역, 풀링/Global Average Pooling, 데이터 증강으로 위치 변화에 **덜 민감하게** 만듦. 기본 CNN 구조만으로 완전한 위치 불변성이 자동으로 생기지는 않음 |

한 문장으로: CNN은 **"옮겨진 고양이를 다시 찾는 것"**은 잘하지만, **"얼마나 옮겨져도 똑같이 취급하는 것"**까지 자동으로 보장하지는 않는다.
