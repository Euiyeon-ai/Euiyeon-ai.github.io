# Q1. 자율주행 카메라 — "이 픽셀은 무엇인가"와 "이 차는 어느 차인가"

> 자율주행 차량이 카메라로 도로 이미지를 분석해요. '이 픽셀들이 차인지 도로인지 사람인지' 구분하는 것과, '왼쪽 차와 오른쪽 차를 서로 다른 개체로 구별'하는 것은 다른 문제예요. 이 둘을 각각 어떤 방식으로 해결할 건가요?

## 한 줄 답

**첫 번째는 시맨틱 세그멘테이션, 두 번째는 인스턴스 세그멘테이션이다.** 시맨틱은 **모든 픽셀에 종류를 하나씩** 붙인다. 그래서 도로 · 차 · 사람 영역은 알지만 **차 두 대는 같은 "차"** 다. 인스턴스는 **개체를 먼저 하나씩 찾고, 개체마다 마스크를 따로** 낸다. 그래서 차 #1과 차 #2가 갈린다.

## 답변

![시맨틱 세그멘테이션과 인스턴스 세그멘테이션의 출력 비교](/images/weekly-paper-10/wp10-q1-sem-vs-inst.svg)

### 1. 문제 — 질문이 두 개이고, 답의 모양이 다르다

| | 질문 ① | 질문 ② |
|---|---|---|
| 묻는 것 | 이 픽셀은 **무엇**인가? | 이 픽셀은 **어느 개체**의 것인가? |
| 자율주행에서 쓰임 | **달릴 수 있는 곳** 찾기 (도로 · 인도 · 차선) | **피해야 할 대상** 하나하나 추적 (앞차 · 옆차 · 보행자) |
| 답의 단위 | 픽셀 | 개체 |
| 이름 | **시맨틱 세그멘테이션** | **인스턴스 세그멘테이션** |

왼쪽 차는 멈춰 있고 오른쪽 차는 끼어들고 있다면, 두 차를 **따로** 알아야 각각의 속도와 방향을 잴 수 있다. "차 픽셀이 이만큼 있다"만으로는 부족하다.

### 2. 원인 — 시맨틱의 출력에는 "몇 번째 차"가 들어갈 자리가 없다

![두 세그멘테이션의 출력 모양](/images/weekly-paper-10/wp10-q1-output-shape.svg)

**① 시맨틱은 픽셀마다 "종류 고르기"다**

출력은 `(클래스 수, H, W)` 크기의 점수이고, 픽셀마다 가장 높은 클래스를 고른다. 고를 수 있는 답이 **도로 · 차 · 사람 …** 뿐이다. "차 1번", "차 2번"이라는 선택지가 없다.

**② 그렇다고 "차 1번, 차 2번"을 클래스로 만들 수도 없다**

- 차가 몇 대 나올지 사진마다 다르다 → 클래스 수를 정할 수 없다
- 어느 차가 1번인지 정할 기준이 없다 → 정답 자체가 모호해진다

**③ 붙어 있는 차는 한 덩어리가 된다**

차 영역을 덩어리로 나눠 세는 방법(connected components)은 차들이 떨어져 있을 때만 통한다. 도로에서는 차가 **겹쳐 보이는 것이 보통**이다. 겹친 두 대는 한 덩어리로 잡힌다.

> **그럼 객체 인식(박스)만 쓰면 안 되나?**
>
> 박스는 개체를 구별하지만 **직사각형**이다. 대각선으로 선 차나 보행자는 박스 안에 도로가 절반이다. 그리고 도로 · 차선 · 하늘처럼 **모양이 정해지지 않고 셀 수 없는 것**은 박스로 잡을 수 없다.
>
> | | 종류 | 개체 구별 | 픽셀 단위 윤곽 | 도로 같은 배경 |
> |---|:-:|:-:|:-:|:-:|
> | 객체 인식 | ✓ | ✓ | ✗ | ✗ |
> | 시맨틱 세그멘테이션 | ✓ | ✗ | ✓ | ✓ |
> | 인스턴스 세그멘테이션 | ✓ | ✓ | ✓ | ✗ |

### 3. 해결책 — 질문마다 다른 모델을 쓴다

| | 시맨틱 세그멘테이션 | 인스턴스 세그멘테이션 |
|---|---|---|
| 푸는 방식 | **픽셀마다 분류** | **개체를 찾고 → 개체마다 마스크** |
| 대표 모델 | FCN · U-Net · DeepLab | Mask R-CNN · YOLO-seg |
| 출력 | 클래스 지도 **1장** `(C, H, W)` | 개체마다 **(박스 + 종류 + 점수 + 마스크)**, 장 수는 사진마다 다름 |
| 정답 데이터 | 픽셀마다 클래스 번호가 적힌 그림 1장 | 개체마다 따로 그린 마스크(또는 다각형) |
| 손실 | 픽셀별 Cross-Entropy (+ Dice) | 분류 + 박스 + **마스크** 손실 |
| 평가 | **mIoU** | **mask AP (mAP)** |

#### ① 시맨틱 — 줄였다가 다시 키운다

분류 CNN은 마지막에 사진 전체를 점수 하나로 뭉친다. 시맨틱 모델은 이 부분을 버리고 **끝까지 지도 모양을 유지**한다.

1. **인코더** : 사진을 줄여 가며 "무엇인지"를 읽는다 (크기 ↓, 의미 ↑)
2. **디코더** : 다시 원래 크기로 키운다 (업샘플링 · 전치 합성곱)
3. **스킵 연결(U-Net)** : 줄이기 전의 선명한 특징을 디코더에 붙여, 흐려진 **경계**를 되살린다

```python
from torchvision.models.segmentation import deeplabv3_resnet50

model = deeplabv3_resnet50(weights="DEFAULT").eval()
out = model(x)["out"]             # (B, C, H, W) : 픽셀마다 클래스 점수
pred = out.argmax(dim=1)          # (B, H, W)    : 픽셀마다 클래스 번호

road_mask = pred == ROAD          # 달릴 수 있는 영역
```

학습은 **픽셀 하나하나를 분류 문제로** 본다. `nn.CrossEntropyLoss`에 `(B, C, H, W)` 점수와 `(B, H, W)` 정답을 그대로 넣으면 된다.

#### ② 인스턴스 — 먼저 찾고, 그 안에서 칠한다

Mask R-CNN은 객체 인식 모델(Faster R-CNN)에 **마스크를 그리는 가지**를 하나 더 붙인 것이다.

1. **후보 영역 찾기** : "여기 물체가 있을 것 같다"는 박스를 낸다
2. **박스마다 종류 + 정확한 위치**를 예측한다 (여기까지가 객체 인식)
3. **박스 안에서만** "이 픽셀이 이 개체인가 / 아닌가"를 칠한다

박스가 이미 개체를 하나씩 갈라 놓았기 때문에, 마스크는 **그 박스의 주인만** 칠하면 된다. 두 차가 겹쳐 있어도 박스가 다르면 마스크도 다르다.

```python
from torchvision.models.detection import maskrcnn_resnet50_fpn

model = maskrcnn_resnet50_fpn(weights="DEFAULT").eval()
pred = model([img])[0]            # {"boxes", "labels", "scores", "masks"}

keep = pred["scores"] >= 0.5
masks = pred["masks"][keep] > 0.5 # (N, 1, H, W) : 개체마다 마스크 1장
labels = pred["labels"][keep]     # (N,)         : 개체마다 종류

n_cars = (labels == CAR).sum()    # 차 대수 = 차 마스크 장 수
```

#### ③ 자율주행에는 둘 다 필요하다 — 파놉틱 세그멘테이션

| 대상 | 예 | 필요한 것 |
|---|---|---|
| **셀 수 없는 배경 (stuff)** | 도로 · 인도 · 하늘 · 건물 | 종류만 → **시맨틱** |
| **셀 수 있는 개체 (things)** | 차 · 사람 · 자전거 | 종류 + 번호 → **인스턴스** |

둘을 합쳐 **모든 픽셀에 (종류, 개체 번호)** 를 붙이는 것이 **파놉틱 세그멘테이션**이다. 도로는 `(도로, -)`, 왼쪽 차는 `(차, 1)`, 오른쪽 차는 `(차, 2)`가 된다.
자율주행 데이터셋 Cityscapes도 이렇게 나뉜다. 평가하는 19개 클래스 중 **사람 · 차 · 버스 등 8개만** 개체 단위 정답이 있다.

> **평가는 왜 서로 다른가?**
>
> | | 지표 | 재는 것 |
> |---|---|---|
> | 시맨틱 | **mIoU** | 클래스마다 "예측 영역과 정답 영역이 얼마나 겹치나"를 구해 평균 |
> | 인스턴스 | **mask AP** | 개체마다 마스크 IoU가 기준을 넘으면 맞힌 것으로 세고, 놓친 개체 · 없는데 그린 개체를 함께 반영 |
>
> 픽셀 정확도는 쓰지 않는다. 도로 사진은 **도로 · 하늘이 대부분**이라, 사람을 전부 놓쳐도 정확도는 높게 나온다. 같은 이유로 시맨틱 학습에는 클래스 가중치나 Dice loss를 함께 쓴다.

> **자율주행이라서 더 신경 쓸 것**
>
> | 상황 | 문제 | 대응 |
> |---|---|---|
> | **실시간** | 마스크까지 그리면 느리다 | 가벼운 모델 · 입력 해상도 조절 · 1단계 방식(YOLO-seg 등) |
> | **멀리 있는 작은 보행자** | 줄어든 특징맵에서 몇 픽셀만 남는다 | 여러 크기 특징맵(FPN) · 고해상도 입력 |
> | **가려진 개체** | 앞차에 가린 차가 두 조각으로 보인다 | 여러 프레임을 이어 추적(tracking) |
> | **밤 · 비 · 역광** | 학습 때 못 본 장면 | 다양한 조건의 데이터 · 밝기 증강 · 라이다 등 다른 센서와 함께 |
> | **정답 만들기 비용** | 픽셀 단위, 그것도 개체마다 그려야 한다 | 사전학습 모델 미세조정 · 라벨링 보조 도구 |

### 4. 변화 — "픽셀 색칠"이 "달릴 곳과 피할 대상"이 된다

| | 시맨틱만 | 시맨틱 + 인스턴스 |
|---|---|---|
| 아는 것 | 도로 · 차 · 사람 **영역** | 영역 + **차 #1, 차 #2, 사람 #1** |
| 할 수 있는 일 | 주행 가능 영역 · 차선 판단 | 개체별 거리 · 속도 추적, 끼어드는 차와 서 있는 차 구분 |

| | |
|---|---|
| **문제** | "이 픽셀은 무엇인가"와 "이 차는 어느 차인가"는 답의 단위가 다르다 (픽셀 vs 개체) |
| **원인** | 시맨틱의 출력은 **픽셀마다 종류 1개**. 개체 번호가 들어갈 자리가 없어 같은 종류는 한 덩어리가 된다 |
| **해결책** | ① **시맨틱** : 인코더-디코더(U-Net · DeepLab)로 픽셀마다 분류 ② **인스턴스** : 개체를 먼저 찾고 개체마다 마스크(Mask R-CNN) ③ 둘을 합치면 **파놉틱** |
| **변화** | 도로 사진이 **주행 가능 영역 + 추적할 개체 목록**이 된다 |

**시맨틱은 "무엇"까지, 인스턴스는 "무엇의 몇 번째"까지 답한다.**
