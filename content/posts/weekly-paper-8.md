# Q1. 불량 검사 모델 — 학습 데이터에선 잘 맞히는데, 새 사진에선 틀린다

> 이미지 5,000장으로 제품 불량 여부를 분류하는 모델을 학습시켰는데, 학습 데이터에서는 정확도가 매우 높지만 실제 새 이미지에서는 성능이 크게 떨어져요. 새로운 이미지를 추가로 촬영하기는 어려운 상황이에요. 어떤 방법을 시도해볼 건가요?

## 한 줄 답

**과적합이다.** 모델이 "불량의 특징"이 아니라 **5,000장의 모습 자체를 외웠다.** 사진을 더 찍을 수 없으니 **있는 사진을 여러 모습으로 바꿔 보여 주고(증강)**, **이미 사진을 잘 보는 모델을 빌려 오고(전이학습)**, **외우기 어렵게 만든다(규제·조기 종료).**

## 답변

### 1. 문제 — 학습 사진은 거의 다 맞히는데, 새 사진은 못 맞힌다

| | 학습 사진 | 새 사진 |
|---|---|---|
| 정확도 | 매우 높음 (예: 99%) | 크게 떨어짐 |

두 점수 사이가 **크게 벌어져 있다** = 과적합의 전형적인 모습.

### 2. 원인 — 문제집 답을 외운 학생

기출문제 답을 통째로 외운 학생은 같은 문제는 100점이지만, **숫자만 바뀌어도** 못 푼다.
모델도 똑같다. 5,000장을 반복해서 보다 보면 **불량 자체(스크래치·찍힘)** 가 아니라 **그 사진들에만 있던 우연한 특징**까지 외운다.

- 학습 사진은 늘 **같은 조명·같은 각도·같은 위치**에서 찍혔다
- 새 사진은 조명이 조금 다르거나, 제품이 조금 기울어져 있다
- 모델 눈엔 **처음 보는 사진** → 틀린다

> **방법을 고르기 전에 먼저 확인할 것 3가지**
>
> | 확인 | 왜 |
> |---|---|
> | **같은 제품 사진이 학습·검증 양쪽에 있나?** | 검증 점수가 부풀려져 과적합을 늦게 알아챈다 |
> | **불량 비율은?** | 정상이 95%면 "전부 정상"만 외쳐도 정확도 95%. 정확도 말고 **Recall·F1**로 봐야 한다 |
> | **새 사진은 무엇이 다른가?** | 조명이 다르면 밝기 증강, 각도가 다르면 회전 증강. **차이를 알아야 처방을 고른다** |

### 3. 해결책 — 새 사진 없이 할 수 있는 5가지

| 순서 | 방법 | 쉽게 말하면 | 효과 |
|:-:|---|---|---|
| ① | **데이터 증강** | 사진 1장을 여러 모습으로 바꿔 보여 준다 | 5,000장을 수만 장처럼 |
| ② | **전이학습** | 사진을 이미 잘 보는 모델(ResNet 등)을 빌려 온다 | 적은 데이터로도 좋은 눈 |
| ③ | **규제** | Dropout·Weight decay로 외우기 어렵게 | 우연한 특징에 덜 매달림 |
| ④ | **조기 종료 + checkpoint** | 외우기 시작하면 멈추고, 가장 좋았던 순간을 저장 | 과적합 직전 모델 사용 |
| ⑤ | **모델 줄이기** | 층·채널을 줄여 외울 공간 자체를 줄임 | 모델이 너무 클 때 |

**가장 먼저 할 것은 ① 증강이다.** "사진을 더 찍을 수 없다"는 조건에 가장 직접적인 답이다.

#### ① 데이터 증강 — 같은 사진, 다른 모습

![데이터 증강: 사진 한 장을 여러 모습으로](/images/weekly-paper-8/wp8-q1-augment.svg)

매 에폭 같은 사진이 **조금씩 다른 모습**으로 들어오니, 모델은 한 가지 모습을 외울 수 없다. 대신 **어떤 모습에서도 변하지 않는 것 = 불량의 특징**을 배운다.

고르는 기준은 딱 하나다. **바꾼 뒤에도 불량/정상을 판단할 단서가 남아 있는가?**

| ✅ 넣기 | ⚠️ 조심 | ❌ 넣지 않기 |
|---|---|---|
| 작은 회전 · 좌우 반전 · 조금 이동 · 밝기/대비 조금 | 블러 (미세한 스크래치가 흐려짐) | 강한 자르기 (결함이 잘려 나감) · 과한 색 변화 |

```python
from torchvision.transforms import v2

train_tf = v2.Compose([
    v2.Resize((224, 224)),
    v2.RandomRotation(15),                          # 제품이 조금 기울어도
    v2.RandomHorizontalFlip(),                      # 좌우가 바뀌어도
    v2.ColorJitter(brightness=0.2, contrast=0.2),   # 조명이 조금 달라도
    v2.ToImage(), v2.ToDtype(torch.float32, scale=True),
    v2.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225]),
])
```

> **증강은 왜 학습할 때만 하고, 검증·테스트에는 안 하나?**
>
> 시험 문제가 볼 때마다 바뀌면 점수를 비교할 수 없다. 검증 점수로 "가장 좋았던 모델"을 골라야 하는데, 점수가 **운에 따라 흔들리면** 고를 수가 없다. 실제로 만날 사진도 찍힌 그대로 들어오니, 검증·테스트는 **원래 사진 그대로** 둔다.

> **증강을 많이, 세게 넣을수록 좋은가?**
>
> 아니다. 증강은 **보여 준 변화에만** 강해진다. (수업 실측: 증강에 넣은 변화는 흔들림 10.7% → 5.4%, 넣지 않은 변화는 49.5% → 46.0%로 거의 그대로)
> 그래서 **새 사진이 실제로 어떻게 다른지**에 맞춰 골라야 한다. 너무 세게 넣으면 정답이 바뀐 사진을 가르치게 된다.

#### ② 전이학습 — 이미 잘 보는 눈을 빌려 오기

ImageNet(120만 장)으로 미리 학습된 모델은 **선·모서리·질감을 보는 눈**이 이미 있다. 우리는 **마지막 분류층만** "정상/불량"으로 바꿔 가르치면 된다.

```python
from torchvision import models
model = models.resnet18(weights=models.ResNet18_Weights.DEFAULT)
for p in model.parameters():
    p.requires_grad = False                    # 빌려 온 눈은 그대로 두고
model.fc = nn.Linear(model.fc.in_features, 2)  # 마지막 층만 정상/불량으로 새로
```

#### ③④ 규제 + 조기 종료 — 외우기 어렵게, 외우기 전에 멈추기

```
정확도 │        ___------ 학습      ← 계속 오름
       │    __/
       │  _/‾‾‾‾‾\___    검증      ← 멈췄다가 내려감
       │ /     ↑
       └───────┼──────── 에폭
            여기서 저장 (checkpoint) · 몇 번 더 안 좋아지면 멈춤 (early stopping)
```

- **Dropout**: 학습할 때 일부 뉴런을 무작위로 끈다 → 특정 뉴런 하나에 의존해 외우기 어려움
- **Weight decay**: 가중치가 너무 커지지 않게 벌점 → 사진 하나하나에 과하게 맞추지 못함
- **Early stopping**: 검증 점수가 몇 번 연속 안 오르면 학습을 멈추고, 가장 좋았던 순간의 모델을 쓴다

### 4. 변화 — 두 점수의 간격이 좁아진다

- 학습 정확도는 **조금 내려갈 수 있다.** 나빠진 게 아니라, 더 어려운(바뀐) 사진으로 시험을 보기 때문이다.
- 대신 **새 사진 정확도가 올라가고**, 학습·검증 점수 사이 간격이 좁아진다.
- 효과를 말하려면 **한 번에 하나만 바꾸고**(예: 증강만 추가), 같은 검증 사진으로 비교한다.

| | |
|---|---|
| **문제** | 학습 사진은 잘 맞히는데 새 사진은 못 맞힌다 |
| **원인** | 불량의 특징이 아니라 **5,000장의 모습 자체를 외움** = 과적합 |
| **해결책** | **증강**(1장을 여러 모습으로) + **전이학습** + **규제·조기 종료** |
| **변화** | 학습 점수는 조금 내려가도, **새 사진 점수가 오르고** 간격이 좁아진다 |

# Q2. 희귀 질환 이미지 300장 — 처음부터 학습시키면?

> 희귀 질환 여부를 판별하는 의료 이미지 300장으로 분류 모델을 처음부터 학습시키려 해요. 이 접근에는 어떤 문제가 있을까요? 어떤 대안을 제안할 건가요?

## 한 줄 답

**300장은 모델을 처음부터 가르치기엔 너무 적고, 환자 사진은 그중에서도 극소수다.** 그래서 **외우기(과적합)** 와 **"전부 정상" 찍기(불균형)** 가 동시에 생긴다. **사전학습 모델을 빌려 오고**, 불균형을 처리하고, **Recall과 교차검증**으로 평가한다.

## 답변

### 1. 문제 — 처음부터 학습하면 생기는 3가지 문제

| 문제 | 한 줄 설명 |
|---|---|
| ① **사진이 너무 적다** | 배울 숫자는 수백만~천만 개인데, 사진은 300장 |
| ② **환자 사진은 더 적다** | 희귀 질환 → 대부분 정상. "전부 정상"이라고 해도 점수가 높다 |
| ③ **점수를 믿기 어렵다** | 검증·테스트가 수십 장뿐 → 한두 장 차이로 점수가 크게 흔들린다 |

### 2. 원인 — 기본기부터 배워야 하는데, 교재가 300쪽뿐

**① 처음부터 = 사진 보는 법부터 배워야 한다**

처음부터 학습하는 모델은 **선이 뭔지, 모서리가 뭔지**부터 배워야 한다. 그 위에 "질환의 특징"을 쌓는다. 300장으로 이 모든 걸 배우기엔 턱없이 부족하다. 결국 **300장을 외워 버린다.**

![처음부터 학습과 사전학습 모델 빌려 오기 비교](/images/weekly-paper-8/wp8-q2-scratch-vs-pretrained.svg)

**② 희귀 질환 = 불균형 → 정확도가 거짓말을 한다**

![희귀 질환 데이터의 클래스 불균형과 정확도 착시](/images/weekly-paper-8/wp8-q2-imbalance.svg)

모델 입장에선 "전부 정상"이라고 답하는 게 **가장 쉽게 점수를 따는 방법**이다. 의료에서 가장 위험한 **환자를 놓치는 실수(FN)** 가 오히려 가장 쉬운 길이 된다.


### 3. 해결책 — 빌려 오고, 균형 맞추고, 제대로 잰다

| 대안 | 무엇을 | 푸는 문제 |
|---|---|---|
| **① 전이학습** (핵심) | ImageNet 또는 **의료 영상으로 미리 학습된 모델**을 빌려 옴 | ① 사진 부족 |
| **② 증강** | 의료 영상에 맞는 약한 변환 (작은 회전·밝기) | ① 사진 부족 |
| **③ 불균형 처리** | 환자 사진에 가중치 · 더 자주 뽑기 | ② 환자 부족 |
| **④ 제대로 평가** | Recall·F1·혼동행렬 + **교차검증** | ② ③ 점수 착시 |

#### ① 전이학습 — 조금씩 풀기

```
Frozen (마지막 층만)  →  Partial (뒤쪽 layer4까지)  →  Full (전부, 아주 작은 lr)
배울 숫자  1,026개           약 840만 개                     약 1,100만 개
◀──── 300장이면 여기서 시작 ────
```

사진이 적을수록 **적게 푼다.** 먼저 Frozen으로 시작하고, 검증 점수가 부족할 때만 뒤쪽 층부터 하나씩 푼다.

> **전부 풀 때(Full) 학습률(lr)을 낮춰야 하는 이유**
>
> 빌려 온 가중치는 이미 잘 학습된 상태다. 큰 걸음으로 고치면 **좋은 기본기를 망가뜨린다.**
> 수업 실측(사진 1,080장): Frozen 82.3% · **Full lr 0.001 → 70.0%** · Full lr 0.0001 → 82.5%
> → 전부 풀려면 lr을 **10~100배 낮춘다.**

> **빌려 올 때 꼭 지킬 것 — 입력 약속**
>
> 빌려 온 모델은 **학습할 때 받던 형식** 그대로 넣어야 한다. (ImageNet 평균·표준편차로 정규화, 224×224, 흑백이면 채널 3개로 복사)
> 어기면 **오류 없이 점수만 무너진다.**

#### ② 증강 — 의료 영상은 더 조심해서

| ✅ 넣기 | ⚠️ 조심 | ❌ 넣지 않기 |
|---|---|---|
| 작은 회전 (±10°) · 밝기/대비 조금 · 약간 이동 | 좌우 반전 (심장·장기 위치는 좌우가 정해져 있음) | 상하 반전 · 강한 자르기 (병변이 잘려 나감) |

#### ③ 불균형 처리

```python
# 환자 사진을 틀리면 벌점을 더 크게 (예: 정상 285 · 환자 15 → 약 1 : 19)
loss_fn = nn.CrossEntropyLoss(weight=torch.tensor([1.0, 19.0]))
```

또는 `WeightedRandomSampler`로 환자 사진을 **더 자주 뽑아** 배치마다 골고루 보이게 한다.

#### ④ 제대로 평가 — Recall + 교차검증

| 지표 | 뜻 | 의료에서 |
|---|---|---|
| **Recall** | 실제 환자 중 찾아낸 비율 | **가장 중요** — 놓치면 안 됨 |
| Precision | "환자"라고 한 것 중 진짜 환자 | 너무 낮으면 불필요한 재검사 |
| F1 | 둘의 균형 | 한 숫자로 비교할 때 |

> **교차검증(K-fold)이 뭐고, 왜 필요한가?**
>
> 300장을 한 번만 나누면, **어떤 사진이 검증에 들어갔느냐(운)** 에 따라 점수가 크게 달라진다. 그래서 5등분해서 **돌아가며** 한 조각씩 검증에 쓰고, 5번 점수의 평균을 본다.
> ```
> 1회차  [검증][학습][학습][학습][학습]
> 2회차  [학습][검증][학습][학습][학습]
> 3회차  [학습][학습][검증][학습][학습]
> 4회차  [학습][학습][학습][검증][학습]
> 5회차  [학습][학습][학습][학습][검증]   → 5번 점수의 평균 ± 흔들림
> ```
> 나눌 때는 **환자 비율이 조각마다 같게** (`StratifiedKFold`) 나눈다. 환자 15장이 한 조각에 몰리면 안 되기 때문이다.

### 4. 변화 — 적은 사진으로도 믿을 수 있는 모델

- 기본기는 빌려 왔으니 300장은 **"질환의 특징"을 배우는 데만** 쓴다 → 과적합이 크게 줄어든다
- 불균형을 처리하고 Recall로 보니 **"전부 정상" 모델을 걸러 낸다**
- 교차검증으로 **운에 덜 흔들리는 점수**를 얻는다

| | |
|---|---|
| **문제** | 희귀 질환 300장으로 처음부터 학습 |
| **원인** | 사진 보는 기본기부터 배우기엔 **데이터 부족** + 환자 사진이 극소수인 **불균형** |
| **해결책** | **사전학습 모델 빌려 오기**(Frozen부터) + 증강 + 불균형 처리 + **Recall·교차검증** |
| **변화** | 적은 사진으로도 과적합이 줄고, **환자를 놓치지 않는지** 제대로 확인할 수 있다 |

**데이터가 적을 땐 처음부터 가르치지 말고, 빌려 온다.**
