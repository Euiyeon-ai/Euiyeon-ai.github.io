# Q1. 긴 리뷰 감성 분류 — 맨 앞 단어가 끝에서 반영되지 않는다

> 긴 영화 리뷰 문장의 감성(긍정/부정)을 분류하는 모델에 기본 RNN을 사용했어요. 그런데 문장 맨 앞에 나온 중요한 단어의 정보가, 문장 끝에서 예측할 때는 거의 반영되지 않는 것 같아요. 어떤 원인을 의심할 건가요? 어떻게 해결할 건가요?

## 한 줄 답

**기울기 소실을 의심한다.** RNN이 기억을 못 해서가 아니라, **"맨 앞 단어를 고쳐라"는 신호가 앞까지 오는 동안 사라져서 못 배운 것**이다. 기억 전용 통로와 문(Gate)이 있는 **LSTM / GRU**로 바꾼다.

## 답변

### 1. 원인 — 고치라는 신호가 맨 앞까지 못 간다

RNN은 단어를 하나씩 읽으며 메모(hidden state) 하나를 다음 칸으로 넘기고, **마지막 메모**로 긍정/부정을 맞힌다.

```
h_새 = tanh( W·h_이전 + U·x_지금 )      # 매 칸 메모를 통째로 새로 만든다
```

틀렸다는 건 **문장 끝**에서 알지만, 고쳐야 할 곳은 **문장 맨 앞**이다. 고치라는 신호(기울기)는 끝에서 앞으로 거슬러 가는데, **한 칸 갈 때마다 같은 값이 또 곱해진다.**

- 곱해지는 값이 1보다 작으면 → 0.5를 100번 곱하면 거의 0 → **기울기 소실**
- 1보다 크면 → 반대로 **기울기 폭발**

![gradient가 문장 끝에서 맨 앞으로 거슬러 가며 매 칸 줄어드는 모습](/images/weekly-paper-7/q1-rnn-vanishing.svg)

여기서 헷갈리면 안 되는 것 : **정보는 앞 → 뒤로 가는 기억, 기울기는 뒤 → 앞으로 가는 수정 신호**다. 사라진 건 기울기다. 그래서 메모 크기(`hidden_size`)를 키워도 소용없다. 메모가 커져도 **곱하는 횟수는 그대로**이기 때문이다. (수업 실측 : RNN 메모를 2배로 키워도 +0.7%p, LSTM으로 바꾸면 +8%p)

### 2. 해결 — LSTM : 기억 전용 통로 + 문 3개

LSTM은 **Cell state**라는 기억 전용 통로를 하나 더 둔다. 이 통로는 메모를 매번 새로 만들지 않고, **남길 만큼 곱하고 새 내용을 더하기만** 한다.

```
C_t = f_t · C_(t-1) + i_t · C̃_t
      이전 기억 × 얼마나 남길지 + 새 내용 × 얼마나 넣을지
```

"최고의"처럼 중요한 단어면 `f_t ≈ 1`로 학습된다 → 기억도, 고치라는 신호도 **거의 그대로** 멀리 간다.

![LSTM 구조 한눈에. Cell state 통로 위에 forget, input, output 세 개의 gate가 달려 있다|700](/images/weekly-paper-7/q1-lstm-glance.svg)

| 문(Gate) | 정하는 것 (0~1) |
|---|---|
| **Forget** | 이전 기억을 얼마나 **남길지** (1 = 다 남김) |
| **Input** | 새 내용을 얼마나 **넣을지** |
| **Output** | 지금 얼마나 **꺼내 쓸지** |

코드는 셀만 바꾸면 된다.

```python
self.lstm = nn.LSTM(input_size=10, hidden_size=32, batch_first=True)
output, (h_n, c_n) = self.lstm(x)     # c_n(Cell state)이 하나 더 나온다
return self.fc(h_n[-1])               # 다 읽은 뒤의 마지막 기억으로 분류
```

**GRU**는 LSTM을 가볍게 줄인 것이다(통로 1개 + 문 2개). 성능은 비슷하고(수업 실측 90.6% vs 90.1%) 계산이 적다 → **여유가 없으면 GRU 먼저.**

### 3. 정확히 말하면 — "해결"이 아니라 "크게 늦춘 것"

LSTM도 Forget gate가 닫히면 RNN처럼 신호가 사라진다. 진짜 강점은 **언제 열고 닫을지를 학습으로 정한다**는 것이다. RNN에는 그 손잡이 자체가 없었다. 그래서 Forget gate는 **열어둔 채로(bias를 1~2로) 시작**하는 게 관례다.

바꾸기 전에 하나만 확인한다. 리뷰 길이를 맞추려고 padding을 했다면 `output[:, -1, :]`은 **빈 칸**을 읽는다. 증상이 똑같으니 `output[idx, lens-1]`로 진짜 마지막 단어를 읽고 있는지부터 본다.

| | |
|---|---|
| **문제** | 문장 맨 앞 단어가 끝에서 반영되지 않는다 |
| **원인** | 같은 값이 칸마다 곱해져 고치라는 신호가 사라짐 = **기울기 소실** |
| **해결책** | 기억 전용 통로(**Cell state**) + 문(**Gate**) → LSTM, 가볍게는 GRU |
| **변화** | 중요한 정보를 오래 유지. 소실을 없앤 게 아니라 **크게 늦춤** |

# Q2. 오토인코더 — 복원 오차는 0인데 입력을 복사만 한다

> 이미지 압축을 위해 오토인코더를 학습시켰는데, 결과를 확인해보니 그냥 입력을 그대로 복사해서 출력하는 것처럼 동작해요. 복원 오차는 거의 0이지만, 정작 유의미한 특징을 학습한 것 같지는 않아요. 어떤 문제가 생긴 것일까요? 어떻게 바로잡을 건가요?

## 한 줄 답

**오토인코더가 정답을 너무 쉽게 복사할 수 있게 되어 있다.** 중간 통로가 넓으면 특징을 고를 필요 없이 입력을 그대로 흘려보내면 된다(항등 매핑). **병목을 좁히거나, 노이즈·규제를 더해 복사로는 못 푸는 문제로 바꾼다.**

## 답변

### 1. 원인 — 복사가 가장 쉬운 답이었다

오토인코더의 원래 목적부터 보면 쉽다.

```
입력 이미지 → 압축 → 중요한 특징만 남김 → 다시 복원
```

원본 정보가 100개라고 하면,

```
정상적인 압축      100개 → 10개 → 100개
문제가 있는 경우   100개 → 100개 → 100개
```

- 중간에 **10개**밖에 못 담으면 모델은 "뭘 남겨야 원본을 잘 복원하지?"를 고민한다 → 이 과정에서 **중요한 특징**을 배운다
- 중간층(latent)이 **너무 크거나**, 입력이 출력으로 바로 이어지는 길(skip connection)이 있으면 고민할 이유가 없다 → **"그냥 그대로 전달하면 loss가 0이잖아?"**

![통로가 넓으면 그대로 흘려보내고, 좁으면 골라 담아야 한다](/images/weekly-paper-7/q2-copy-vs-bottleneck.svg)

그래서 복원 오차는 거의 0인데 압축도, 특징 학습도 안 됐다. 이걸 **항등 매핑(identity mapping)을 학습했다**고 한다. 모델 잘못이 아니다. 우리가 요구한 건 "똑같이 내놓아라" 하나뿐이고, 모델은 그걸 가장 쉬운 방법으로 해냈다.

### 2. 해결 ① — 병목(bottleneck)을 좁힌다

가장 먼저 할 일이다.

```
784 → 256 → 128 → 16 → 128 → 256 → 784
```

중간을 16차원까지 강하게 줄이면 모든 정보를 들고 갈 수 없다 → **중요한 특징만 골라서** 저장해야 한다. 이미지 압축이 목적이라면 이 16칸이 곧 압축 파일이다.

### 3. 해결 ② — 복사로는 못 맞히게 한다 (Denoising AE · 규제)

```
노이즈 낀 이미지 → Encoder → 압축 특징 → Decoder → 깨끗한 이미지
```

입력과 정답이 달라지므로, 그대로 복사하면 **노이즈까지 복사돼서 틀린다.** 노이즈를 걷어내려면 이미지의 구조를 알아야 한다.

```python
noisy = (x + 0.3 * torch.randn_like(x)).clamp(0, 1)
loss  = F.mse_loss(model(noisy), x)      # 넣는 건 noisy, 정답은 깨끗한 x
```

그 밖에 latent 값이 조금만 켜지도록 벌점을 주는 **Sparse AE**, weight decay · dropout 같은 **규제**도 같은 효과를 낸다.

### 4. 고친 뒤 — 복원 오차는 올라가는 게 정상

통로를 좁히면 복원 오차는 반드시 오른다. 나빠진 게 아니라 이제야 모델이 **"무엇을 버릴지" 고르기 시작했다**는 뜻이다. 복사에서 벗어났는지는 **무작위 노이즈**를 넣어 보면 안다. 그것까지 완벽히 복원하면 아직 복사 중이고, 못 그리면 데이터의 패턴을 배운 것이다.

| | |
|---|---|
| **문제** | 복원 오차는 0인데 특징을 못 배웠다 |
| **원인** | 통로가 넓어 **그대로 복사**하는 게 가장 쉬운 답 = 항등 매핑 |
| **해결책** | **병목을 좁힌다** + Denoising · Sparse · 규제로 복사를 막는다 |
| **변화** | 복원 오차는 조금 오르지만, 중요한 특징을 골라 담기 시작한다 |

**복원 오차가 0이라고 좋은 오토인코더는 아니다.**
